# Internationalization (i18n)

`@jeyabbalas/data-table` ships every user-facing string through a typed
`Strings` interface — button labels, placeholders, ARIA announcements, chip
descriptions, pluralization templates, validation messages. Override as
many or as few as you like, at construction time, and the table renders
in the language of your choice.

## You'll learn how to

- Override a handful of strings without rewriting the full `Strings` object
- Translate the library into a new locale
- Keep locale grammar (word order, pluralization) inside your translation
- Avoid the common pitfall of trying to hot-swap strings at runtime

## Prerequisites

- Read: [API reference — `Strings` interface](../api-reference.md#i18n), [API reference — `messages` option](../api-reference.md#createdatatable)
- Runnable example: [`examples/07-i18n-french`](../../examples/07-i18n-french/)

## Minimal example

```ts
import { createDataTable } from '@jeyabbalas/data-table';

await createDataTable({
  container,
  source,
  messages: {
    common: {
      close: 'Fermer',
      cancel: 'Annuler',
      apply: 'Appliquer',
    },
    filters: {
      activeFiltersLabel: 'Filtres actifs',
      panelTitleForColumn: (column) => `Filtre : ${column}`,
    },
  },
});
```

Only the overridden strings are replaced; everything else falls back to the
English defaults exported as `defaultStrings`.

## The `Strings` interface

[`src/core/Strings.ts`](../../src/core/Strings.ts) defines the full shape.
Strings are grouped by feature:

| Category     | Contents                                                                                                                                                                                                                                                        |
| ------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `common`     | Shared buttons: close, cancel, apply, confirm, validate, yes/no, deleteConfirm                                                                                                                                                                                  |
| `filters`    | Filter panel, filter bar, filter chips, SQL filter modal, validation messages                                                                                                                                                                                   |
| `presets`    | Filter preset panel, save/load/rename buttons, export/import feedback                                                                                                                                                                                           |
| `export`     | Export dialog: format selector, scope selector, CSV/JSON options, copy/download feedback                                                                                                                                                                        |
| `derived`    | Derived-column modal: name, type, expression editor, vector entry, validation                                                                                                                                                                                   |
| `a11y`       | Live-region announcements, ARIA labels for row/column controls                                                                                                                                                                                                  |
| `statistics` | Stats lines under each column header: row counts, min/max, distinct counts exact and approximate (`uniqueCount`, `approxUniqueCount`, `approxUniquePercent`), selection/hover detail labels (`binLabel`, `categoryLabel`, `selectionRowCount`, `matchCount`, …) |
| `errors`     | Error messages surfaced to users                                                                                                                                                                                                                                |

Most leaves are plain strings. Some are **functions** that take runtime
arguments — that's deliberate, so locale grammar stays in your translation
rather than a string-format DSL:

```ts
// English default:
rowWord: (count) => count === 1 ? 'row' : 'rows',

// Turkish — no plural-agreement based on count:
rowWord: (_count) => 'satır',

// French — "rang" plural is "rangs":
rowWord: (count) => count === 1 ? 'rang' : 'rangs',
```

## `DeepPartial<Strings>`

The `messages` option accepts a deep-partial: every nested object is
optional. Function-typed leaves are replaced wholesale (no partial
application — you give the full implementation or none).

```ts
type DeepPartial<T> = T extends (...args: unknown[]) => unknown
  ? T
  : T extends object
    ? { [K in keyof T]?: DeepPartial<T[K]> }
    : T;
```

So you can provide just `{ filters: { activeFiltersLabel: 'Filtres actifs' } }`
without having to fill in every other filter-panel string.

## Merging with defaults

The facade uses a helper (`mergeStrings`) to compose your overrides with the
English defaults. Both `mergeStrings` and `defaultStrings` are exported from
the root entry for custom wrapping:

```ts
import { mergeStrings, defaultStrings } from '@jeyabbalas/data-table';

const messages = mergeStrings(defaultStrings, {
  common: { close: 'Fermer' },
});

await createDataTable({ container, source, messages });
```

## Translating a full locale

Build a `DeepPartial<Strings>` covering every string. For a concrete
example see
[`examples/07-i18n-french/fr.ts`](../../examples/07-i18n-french/fr.ts). The
pattern is:

```ts
import type { Strings, DeepPartial } from '@jeyabbalas/data-table';

export const fr: DeepPartial<Strings> = {
  common: {/* … */},
  filters: {/* … */},
  presets: {/* … */},
  export: {/* … */},
  derived: {/* … */},
  a11y: {/* … */},
  statistics: {/* … */},
  errors: {/* … */},
};
```

Then in your app:

```ts
import { fr } from './fr';
await createDataTable({ container, source, messages: fr });
```

Missing leaves fall back to English — useful when you want to ship a
locale incrementally.

## ARIA and screen-reader strings

Strings under `a11y` and `filters.ariaLabels` drive the `aria-live`
region and ARIA labels on interactive controls. Translate these carefully:
they're the primary user-facing text for screen-reader users.

```ts
messages: {
  a11y: {
    filtersActiveAnnouncement: (count, filtered, total) =>
      `${count} filtre(s) actif(s), ${filtered.toLocaleString()} sur ${total.toLocaleString()} lignes affichées`,
    sortAnnouncement: (columns) =>
      columns.length === 0
        ? 'Tri désactivé'
        : `Trié par ${columns.map((c) => `${c.column} (${c.direction === 'asc' ? 'croissant' : 'décroissant'})`).join(', puis par ')}`,
  },
};
```

## Recipes

### Localize just the export dialog

```ts
messages: {
  export: {
    title: 'Exporter les données',
    formatLabel: 'Format',
    scopeLabel: 'Portée',
    scopeAll: 'Toutes les lignes',
    scopeFiltered: 'Lignes filtrées',
    downloadButton: 'Télécharger',
  },
};
```

### Translate pluralization differently per language

```ts
// English
rowWord: (count) => count === 1 ? 'row' : 'rows',

// Polish — three forms
rowWord: (count) => {
  if (count === 1) return 'wiersz';
  const tens = count % 100;
  if (tens >= 12 && tens <= 14) return 'wierszy';
  const ones = count % 10;
  if (ones >= 2 && ones <= 4) return 'wiersze';
  return 'wierszy';
},
```

### Runtime language switch

The library resolves messages once at construction. To switch languages at
runtime, destroy and recreate the table:

```ts
async function setLocale(locale: 'en' | 'fr' | 'es') {
  await table.destroy();
  table = await createDataTable({
    container,
    source: currentSource,
    messages: localeMessages[locale],
  });
}
```

An alternative — don't do this — is to mutate the resolved messages object
after construction; UI won't re-render until components re-read the strings,
which doesn't happen consistently.

## Phase 8 — newly translatable strings

Phase 8 added five user-facing strings that previously bypassed the
`Strings` system. Override them like any other key — English defaults
populate when omitted.

| Key                                | Default                                       | Surface                                                                                                           |
| ---------------------------------- | --------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| `derived.expressionPlaceholder`    | `Enter SQL expression, e.g. price * quantity` | Placeholder text inside `DefaultExpressionEditor`'s textarea                                                      |
| `derived.availableColumnsLabel`    | `Available columns:`                          | Prefix shown before the column-hint list under `DefaultExpressionEditor`                                          |
| `export.includeSystemColumnsLabel` | `Include system columns (e.g. __rowid__)`     | Checkbox label in the Export dialog (only shown when the schema has any `system: true` columns, e.g. `__rowid__`) |
| `a11y.resizeHandleLabel`           | `Resize column`                               | `aria-label` on the column-resize drag handle                                                                     |
| `a11y.loadingRowLabel(n)`          | `Loading row ${n}…`                           | Placeholder text shown for not-yet-fetched rows during fast scroll                                                |

The two `a11y.*` keys flow through `ColumnResizer` and `TableBody`
respectively — both classes (Tier-2, exported from `/advanced`) gained
an optional `messages?: Strings` constructor option so custom modal
authors can forward the table's `messages` bundle. The bundled
`TableContainer` and `ColumnHeader` plumb this automatically.

A new meta-test, `tests/i18n/hardcodedStringsScan.test.ts`, scans
`src/` for `textContent =`, `placeholder =`, and
`setAttribute('aria-label' …)` literals on every PR. Any new hardcoded
English string fails the test and forces the author to either route it
through `Strings` or extend the allowlist with a one-line justification.

## Column layout mode strings

The `Shift+F2` keyboard gesture for column resize and reorder (see the
[accessibility guide](./accessibility.md#column-layout-mode-shiftf2)) is
invisible without its live-region text — a width and a position are not
things the grid announces on its own. Every string it speaks is a
function-typed `a11y` leaf.

| Key                                         | Default                                                   | Surface                                          |
| ------------------------------------------- | --------------------------------------------------------- | ------------------------------------------------ |
| `a11y.columnLayoutModeEntered(column)`      | `…: column layout mode. Left and Right resize, …`         | Spoken on entry; it is the mode's whole key map  |
| `a11y.columnWidthAnnouncement(column, px)`  | `${column} ${px} pixels wide`                             | After a resize step, and at the end of a drag    |
| `a11y.columnWidthAtMinimum(column, px)`     | `${column} ${px} pixels wide, minimum`                    | A resize step that landed on the 50px floor      |
| `a11y.columnWidthAtMaximum(column, px)`     | `${column} ${px} pixels wide, maximum`                    | A resize step that landed on the 500px ceiling   |
| `a11y.columnMovedAnnouncement(c, pos, tot)` | `${c} moved to column ${pos} of ${tot}`                   | After a keyboard move, and after a drag-and-drop |
| `a11y.columnMoveBlockedPinned(column)`      | `${column} is pinned and cannot be moved`                 | A move refused because the column is pinned      |
| `a11y.columnLayoutCancelled(column)`        | `${column} layout cancelled, width and position restored` | `Escape`                                         |
| `a11y.columnLayoutCommitted(column)`        | `${column} layout committed`                              | `Enter`, or leaving the grid                     |

`a11y.dragHandleTitle` and `a11y.resizeHandleLabel` also name the key —
`Reorder column (keyboard: Shift+F2 on the header)` and
`Resize column (keyboard: Shift+F2 on the header)`. Keep the key name in a
translation: those two strings and the entry announcement are the only places
a user finds out the gesture exists.

## The grid's accessible name

| Key              | Default      | Surface                                                                                    |
| ---------------- | ------------ | ------------------------------------------------------------------------------------------ |
| `a11y.gridLabel` | `Data table` | `aria-label` on the `role="grid"` element — how a screen reader names the table as a whole |

This string was hardcoded in `TableContainer` until the ARIA-grid keyboard fix
(issue #84) moved the grid semantics onto their own element. The scanner above
did not catch it: its "does this file route _anything_ through `messages.*`"
heuristic exempts the whole file once any call site does, so a single unrouted
literal in an otherwise i18n-aware file slips through. Route new strings
deliberately rather than relying on the scan.

Override it when the table has a more specific identity than "the table":

```ts
await createDataTable({
  container,
  source,
  messages: { a11y: { gridLabel: 'Patient cohort' } },
});
```

## Approximate distinct counts

Above 100,000 rows the column-stats line reports distinct values from a
HyperLogLog sketch rather than an exact count (see
[Visualizations → Distinct counts are approximate](./visualizations.md#distinct-counts-are-approximate-above-100000-rows)).
That needs its own strings, because a translation of the exact form
would present an estimate as a fact.

| Key                                        | Default                 | Surface                                                                                                                                                                      |
| ------------------------------------------ | ----------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `statistics.approxUniqueCount(count)`      | `~1,234 unique`         | `string` columns above the threshold — the approximate twin of `uniqueCount`                                                                                                 |
| `statistics.approxUniquePercent(count, p)` | `~1,234 unique (98%)`   | `uuid` columns above the threshold — the approximate twin of `uniquePercent`                                                                                                 |
| `statistics.approxOtherCategory(count)`    | `Other (~1,234 values)` | The folded "Other" segment above the threshold — the approximate twin of `otherCategory`. Only the folded _distinct_ count is an estimate; the segment's row count is exact. |

**Keep an approximation marker in the translation.** The leading `~` is the
only thing that distinguishes an estimate from an exact count in that line;
a locale where `~` reads as something else should substitute its own hedge
(`≈`, `env.`, `ca.`, `약`) rather than drop it.

```ts
messages: {
  statistics: {
    approxUniqueCount: (count) => `≈ ${count.toLocaleString('de-DE')} eindeutig`,
    approxUniquePercent: (count, pct) =>
      `≈ ${count.toLocaleString('de-DE')} eindeutig (${pct} %)`,
  },
}
```

Both are function-typed, so number formatting stays yours; `pct` arrives
already clamped to 100, since a HyperLogLog estimate can exceed the true
count and `(103%)` reads as a bug. The exact forms `uniqueCount` /
`uniquePercent` are still used at or below 100,000 rows, so translate all
four.

## Gotchas

- **Messages resolve once at construction.** Changing them in memory after `createDataTable()` won't re-render existing components. Destroy + recreate to switch locale.
- **Function strings replace wholesale, not partially.** If you override `rowWord`, provide the full function — the library doesn't call the English default as a fallback for in-function behavior.
- **Missing keys fall back to English.** That's deliberate — you can ship partial translations — but it means untranslated UI appears in English, not as a blank label.
- **ARIA announcements are read aloud.** Test with a real screen reader (VoiceOver, NVDA) after translating `a11y` strings; grammar matters more there than in chrome labels.
- **No built-in locale detection.** The library doesn't read `navigator.language`. Pick your locale in your app and pass it in; defaults are English.
- **Date and number formatting.** The library leaves numeric/date formatting to `toLocaleString()` and to the host-app's `Intl` usage. Per-locale number formats are your responsibility.
