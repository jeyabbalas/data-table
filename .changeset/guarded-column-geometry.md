Hardening pass over the column-geometry and lazy-visualization work: six defects found by a review across the three preceding releases, none of which changes an intended contract.

**Fixed**

- **A column width the renderer cannot use no longer desynchronizes the table.** `setColumnWidth()` validates nothing and a restored session snapshot copies `columnWidths` in wholesale, so a `NaN`, an `Infinity` or a negative number is reachable without malice. Only the internal prefix sums guarded against one; every site that wrote a width to the DOM read the raw value. `width: NaNpx` is rejected by CSSOM, so the element silently kept whatever width it had — for a recycled row, some other column's — while the table's own geometry moved on to the 150 px default, and the header, the cells and the horizontal scroll extent disagreed for every column to the right. All of them now resolve the width the same way: finite and non-negative, rounded, or the default. A negative width additionally made the internal prefix sums non-monotonic, which put the column window's binary search outside its precondition and made the rendered range arbitrary rather than merely wrong. `0` is still a legitimate width and is unaffected.
- **A categorical column above 100,000 rows no longer drops a category from its chart.** Above that threshold the distinct count is a HyperLogLog estimate, and the "Other" segment was gated on `distinctCount > 10` — the same 10 that limits the top-categories query. A column with 11 distinct values whose estimate read 10 rendered no "Other" segment at all, and the 11th category's rows vanished from the bar. The segment is now decided from exact row arithmetic (`non-null rows − Σ top counts > 0`), which is positive exactly when the limit truncated. The folded *distinct* count is still derived from the estimate, so it is now marked as one; the segment's row count was always exact.
- **A host whose visualization root is not mounted yet no longer loses lazy chart creation permanently.** `getRoot()` returning `null` on the first sync latched the controller into creating every chart eagerly for the life of the table — the 1,000-canvas, ~2,000-query behaviour lazy creation exists to remove, restored silently with no error. A missing root is now retried on the next sync; only a genuinely absent `IntersectionObserver` (jsdom, very old browsers) still latches.
- **One throwing stats panel no longer abandons the panels queued behind it.** A custom `refresh` that rejects is routed to the error handler per column, the way the chart path already did it, instead of rejecting into a fire-and-forget caller as an unhandled rejection.
- **A host that writes a column width from `onRowsRendered` on every render no longer overflows the stack.** Replaying the write re-entered the width path from the top, so what a comment described as "replayed once" was an unbounded recursion whenever the replay also moved the column window. It is now bounded at four replays, after which a `console.warn` names the cause.
- **A body row built by hand through `/advanced` no longer has a spacer width written onto one of its cells.** The render path matched the spacer by child position only; on a structurally short row that position holds a real cell, which then stretched by the combined width of every column behind the spacer.

**Added**

- `messages.statistics.approxOtherCategory(count)` — the approximate twin of `otherCategory`, defaulting to `Other (~1,234 values)`. Used for the folded distinct count above the approximation threshold, for the same reason `approxUniqueCount` exists: a translation of the exact form would present an estimate as a fact. Keep the marker in your translation.
- **Eight types are now nameable from `/advanced`**, all of them already reachable through a public signature and previously impossible to write down. `NumericHistogramSnapshot`, `DateHistogramSnapshot`, `TimeHistogramSnapshot`, `IntervalHistogramSnapshot` and `ValueCountsSnapshot` are what each class's `exportDataSnapshot()` returns; `StatsPanelCoordinatorOptions` is `StatsPanelCoordinator`'s trailing constructor argument; `FilterFanOutScheduler` and `FilterFanOutRequest` are the `options.vizScheduler` seam both coordinators accept. Type-only exports — no runtime surface changes. `VisualizationOptions.themeWatcher` is now marked `@internal` instead: it is facade-only wiring, and nothing outside `createDataTable()` can construct a `ThemeWatcher` to pass.
